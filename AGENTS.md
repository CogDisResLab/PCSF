# AGENTS.md

Guidance for coding agents working in the **PCSF** R package.

## 1. What this package is

PCSF (Prize-Collecting Steiner Forest) is an R package that interprets
high-throughput biological data (e.g. phosphoproteomics) against a protein
interaction network. It computes a **prize-collecting Steiner forest** — a
subnetwork that connects a set of "terminal" (prize) nodes at minimum cost —
using a divide-and-conquer matheuristic (Akhmedov et al. 2016/2017). The
core solver is written in C++ and exposed to R through Rcpp.

The package is being readied for **Bioconductor** submission; it is a
dependency of several downstream packages, so API stability and clean
`R CMD check` matter.

- **Version:** 0.99.76 (development version; `0.99.x` = pre-release)
- **License:** MIT + file LICENSE
- **R:** >= 4.0.0
- **Repo:** https://github.com/CogDisResLab/PCSF

## 2. Architecture

Two layers:

- **R layer** (`R/`): user-facing functions, data, plotting, enrichment.
- **C++ layer** (`src/`): the actual Steiner-forest solver, bridged via Rcpp.

### 2.1 C++ core (`src/PCSF.cpp`)

The single exported C++ function is `call_sr` (registered in
`src/RcppExports.cpp`, wrapped in `R/RcppExports.R`). It takes edge
endpoints (`from`, `to`), edge costs, node names, and node prizes, and
returns the selected forest.

Internally it uses **Boost Graph** (via the `BH` package) with:
- `Node` class (children, father, size, price)
- `VertexProperties` struct
- BFS / Dijkstra / Prim / connected-components routines
- The divide-and-conquer matheuristic loop

**Do not hand-edit `R/RcppExports.R` or `src/RcppExports.cpp`** — they are
generated by `Rcpp::compileAttributes()`. To change the C++ signature, edit
`src/PCSF.cpp` and re-run `Rcpp::compileAttributes()`.

### 2.2 R exports (`NAMESPACE`, generated by roxygen2)

| Function | Purpose |
|---|---|
| `PCSF` | Main solver. Params: `ppi`, `terminals`, `w` (2), `b` (1), `mu` (0.0005), `dummies` |
| `PCSF_rand` | Randomized variant. Adds `n` (10), `r` (0.1) |
| `construct_interactome` | Build an `igraph` network from a PPI table |
| `enrichment_analysis` | Functional enrichment. Params: `subnet`, `mode` (0=EnrichR, 1=topGO), `gene_universe` |
| `plot.PCSF` (S3) | Plot a `PCSF` result. Params: `style` (0/1), `edge_width` (5), `node_size` (40), `node_label_cex` (30), `Steiner_node_color` ("lightblue"), `Terminal_node_color`, legends, `extra_node_colors` |
| `plot.PCSFe` (S3) | Plot an `enrichment_analysis` result. Params: `edge_width` (5), `node_size` (30), `node_label_cex` (1), legends, `extra_node_colors` |

Internal helpers (not exported):
- `call_sr` — Rcpp bridge to the C++ solver (`R/RcppExports.R`)
- `call_enr` — EnrichR API client via `httr::POST`
  (`http://amp.pharm.mssm.edu/Enrichr/addList` and `/export`);
  databases: GO_Biological_Process_2015, KEGG_2016, Reactome_2016, BioCarta_2016

## 4. R coding conventions

Enforced by `.lintr` and the pre-commit `styler` hook. **Match these exactly.**

- **Naming:** `camelCase` for objects/functions (`object_name_linter`).
- **Indentation:** 4 spaces, `hanging_indent_style = "never"`.
- **Line length:** 80 columns.
- **No tabs** (forbidden by pre-commit `forbid-tabs`).
- **No CRLF** (LF line endings only).
- **Documentation:** roxygen2 with `markdown = TRUE`
  (`Config/roxygen2/version: 8.1.0`). Every exported function needs a full
  roxygen block (`@param`, `@return`, `@examples`, `@author` where relevant).
  Regenerate docs with `roxygen2::roxygenise()`.
- **Lint tags:** default, style, misc, potential-bug, performance,
  documentation, risky, package_development.
- **Excluded from lint:** `renv/activate.R`, `doc/`.
- **`object_usage_linter` is disabled** — do not rely on it.

### 4.1 Pre-commit hooks

Configured in `.pre-commit-config.yaml`. Run `pre-commit run --all-files`
before committing. Notable hooks:
- `use-tidy-description`, `codemeta-description-updated`, `spell-check`
- `readme-rmd-rendered`, `parsable-R`, `no-browser-statement`,
  `no-debug-statement`, `deps-in-desc`
- `styler` (tidyverse style, indent 4) + `lintr`
- `bump-version` (pre-commit, runs `utilities/bump-version.sh`)
- `codemeta-json-updated` (on DESCRIPTION change)
- `create-version-tag` (post-commit, runs `utilities/create_tag.sh`)
- `conventional-pre-commit` — commit messages must follow Conventional
  Commits (types: build, chore, ci, docs, feat, fix, perf, refactor,
  revert, style, test, bump)
- `no-commit-to-branch` — never commit directly to `devel` or `RELEASE.*`
- `forbid-to-commit` — never commit `.Rhistory`, `.RData`, `.Rds`, `.rds`

## 5. C++ conventions

- C++11, compiled via Rcpp + Boost Graph (`BH`).
- Keep the solver in `src/PCSF.cpp`; the only R-facing entry point is
  `call_sr`. Preserve its signature unless the R wrapper is updated in lockstep.
- After changing `src/PCSF.cpp`, run `Rcpp::compileAttributes()` to
  regenerate `R/RcppExports.R` and `src/RcppExports.cpp`.
- Do not introduce new external dependencies beyond `BH` and `Rcpp`
  (the only `LinkingTo` packages).

## 6. Testing

- Harness: `tests/testthat.R` runs `test_check("PCSF")`.
- **There is currently no `tests/testthat/` subdirectory** — no unit tests
  exist yet. New tests go in `tests/testthat/test-*.R`.
- `Config/testthat/edition: 3` — use testthat 3e idioms
  (`test_that`, `expect_*`, `expect_error` with `class`/`regexp`).
- `testthat (>= 3.0.0)` is in `Suggests`.
- Run tests with `R CMD check` or `devtools::test()`.

## 7. Known issues (Bioconductor readiness)

These are the main gaps to close before submission:

1. **Stale example API.** `examples/01_basic_usage.R`,
   `02_randomized_usage.R`, `04_plotting_examples.R` use the **old** parameter
   names (`k`, `alpha`, `beta`, `gamma`, `n_iter`, `n_cores`, `seed`) instead
   of the current API (`w`, `b`, `mu`, `n`, `r`). Update them to match the
   current signatures in §2.2.
2. **Missing example.** `examples/03_enrichment_analysis.R` does not exist;
   create it to demonstrate `enrichment_analysis()`.
3. **No unit tests.** Add `tests/testthat/` coverage for the exported
   functions.
4. **Vignette.** `vignettes/PCSF-manual.Rmd` (authors Murodzhon Akhmedov
   et al., Feb 21 2017) should be reviewed for current API and rendered
   cleanly.

## 11. Workflow checklist for changes

1. Edit source following §4 / §5 conventions.
2. If C++ changed: `Rcpp::compileAttributes()`.
3. If roxygen changed: `roxygen2::roxygenise()`.
4. Run `pre-commit run --all-files`.
5. Run `R CMD check` (or `devtools::check()`).
6. Commit with a Conventional Commits message; never commit to `devel`/`RELEASE.*`.
